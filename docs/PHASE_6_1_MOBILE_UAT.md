# Phase 6.1 — Mobile UAT บนอุปกรณ์จริง

วันที่จัดทำ: **23 ตุลาคม 2026 (Asia/Bangkok)**

แอป: **Our Little World 💗**

Production: <https://our-little-world.supawat-you.workers.dev/>

ฐานที่นำมาตรวจ: GitHub `main` commit **`90f2c5a`** ตามสถานะก่อนเริ่ม Phase 6.1

เอกสารนี้เป็นแผนและแบบบันทึกผลสำหรับเจ้าของโปรเจกต์กับผู้ทดสอบ **ยังไม่ใช่หลักฐานว่าเครื่องจริงผ่าน** ผลจาก Playwright, viewport จำลอง, virtual authenticator หรือ Push ที่จำลอง ต้องบันทึกในรายงาน automated QA แยกต่างหาก ห้ามเปลี่ยนแถวเครื่องจริงเป็น PASS จากผลเหล่านั้น

## 1. ขอบเขตและกติกาการบันทึกผล

- ทุกกรณีในตารางเริ่มต้นด้วย Actual = **ยังไม่ได้ทดสอบบนเครื่องจริง** และ Status = **NOT TESTED** ผู้ทดสอบแก้สองช่องนี้เมื่อได้ลงมือจริง พร้อมระบุหมายเลขหลักฐาน
- ใช้ **PASS** เมื่อทำครบและผลตรง Expected, **FAIL** เมื่อพบผลผิด, **BLOCKED** เมื่อมีข้อจำกัดที่ระบุได้ เช่น ไม่มีอุปกรณ์หรือยังไม่มีรุ่นใหม่ที่ได้รับอนุมัติ, **NOT TESTED** เมื่อยังไม่ได้ทำ ห้ามใช้ PASS แทนการข้ามข้อ
- ผลเป็นรายรุ่นอุปกรณ์/OS/browser/โหมดเปิดแอป ไม่สรุปรวมว่า “iPhone ผ่าน” จากการทำบน Android หรือ Safari บน Mac
- ตรวจผู้ใช้จริงได้เฉพาะอ่านข้อมูลตามสิทธิ์ของตนเอง กรณีเพิ่มข้อมูล ทดสอบซ้ำ จับคู่ ล็อกเอาต์ กู้คืน หรือเพิกถอนสิทธิ์ ให้ใช้บัญชี UAT ที่เจ้าของสร้างแยกและอนุญาตไว้ ห้ามนำบัญชีคนอื่นหรือข้อมูลคู่จริงมาใช้เป็น fixture
- ไม่ลบบัญชี ไม่รีเซ็ตข้อมูล ไม่ล้าง website data/Passkey ของผู้ใช้จริง ไม่เปลี่ยนเวลาระบบเพื่อหลอก session หรือจดหมาย ไม่แก้ Secrets, Production Bindings หรือ Schema และไม่เปิดบริการเสียเงิน
- เอกสารนี้ไม่อนุญาต deploy รุ่นใหม่ การทดสอบอัปเดตต้องรอเจ้าของอนุมัติ release หรือใช้ preview ที่แยกจาก production โดยผู้ดูแลจัดเตรียม

## 2. สิ่งที่ตรวจพบจากโค้ดและนำมาเป็น Expected

ตรวจ `src/components/auth-forms.tsx`, `pairing-forms.tsx`, `pwa.tsx`, `push-tools.tsx`, `backup-tools.tsx`, `quests.tsx`, `savings.tsx`, `us.tsx`, `app-shell.tsx`, `src/lib/auth.ts`, `client-safety.ts`, `push-service.ts`, `src/app/manifest.ts`, `layout.tsx`, `globals.css` และ `scripts/service-worker.js` ก่อนเขียนคู่มือนี้

- สมัครด้วย **ชื่อของคุณ** และ **ชื่อผู้ใช้** (`a–z`, `0–9`, `_`, 3–32 ตัว) แล้วกด **สมัครด้วย Passkey**; Login ไม่กรอกรหัสผ่าน ใช้ **เข้าสู่ระบบด้วย Passkey** และต้องยืนยันตัวตนกับเครื่อง
- Passkey สำรองอยู่หน้า `/account`; ต้อง login ใหม่เมื่อ session ที่ใช้ยืนยันตัวตนเก่ากว่า 15 นาที Session ปกติตั้งอายุ 7 วัน มีการต่ออายุเมื่อเข้าเงื่อนไขใช้งาน จึงห้ามถือว่าแค่รอครบ 7 วันระหว่างใช้งานต่อเนื่องจะทำให้หมดอายุเสมอ
- จับคู่ที่ `/pairing`: คนแรก **สร้างคู่ของเรา** คนเดียว อีกคนใช้ **จับคู่บัญชี** จากรหัส 64 ตัว รหัสใช้ครั้งเดียวภายใน 24 ชั่วโมง การสร้างใหม่แทนรหัสเดิมและ refresh ไม่แสดงรหัสลับเดิม
- หน้า Shared ที่พร้อมใช้แสดง **SHARED · D1** ข้อมูล Demo ในเครื่องแยกจากข้อมูลบัญชีจริง หลัง sign-in และจับคู่แล้ว **หน้า Home ใช้ข้อมูลคู่จริง** เช่น ชื่อ หัวใจ ภารกิจ เงินออม แผน และแมว; เฉพาะวงล้อและ device settings บางส่วนยังเป็นค่าท้องถิ่น อย่าใช้ Demo เป็นหลักฐานการ sync
- Manifest ใช้ `display: standalone`, `scope: /`, `start_url: /`, ภาษาไทย และไอคอน 192/512; `viewportFit: cover` และ CSS ใช้ safe area ด้านบน/ล่าง แต่ต้องดูด้วยตาบนอุปกรณ์จริง
- Service Worker เก็บเฉพาะ public assets ตาม allowlist ไม่เก็บ `/api/`, session, รูปส่วนตัว หรือเนื้อหาจดหมาย ไม่ส่ง POST หรือรายการเงิน/หัวใจจาก background queue
- ออฟไลน์แบบแอปยังเปิดค้างอยู่ อ่านข้อมูลที่โหลดไว้ในรอบนั้นได้ รวมถึงรูปหรือเนื้อหาจดหมายที่โหลดและแสดงค้างอยู่ใน DOM/หน่วยความจำได้ การตัดอินเทอร์เน็ตไม่ได้รับรองว่าจะลบสิ่งที่แสดงแล้วทันที **การโหลดรูปส่วนตัวหรือเนื้อหาจดหมายใหม่ต้องออนไลน์**; การเปิด/โหลดแอปใหม่ต้องออนไลน์เพื่อยืนยันบัญชี Service Worker ไม่เก็บข้อมูลส่วนตัวเหล่านี้สำหรับเปิดใหม่ออฟไลน์
- รุ่นใหม่รอให้กด **อัปเดตแอป** เอง มี guard สำหรับแบบฟอร์ม/งานกำลังบันทึก และหน้าต่างอื่น การแจ้งเตือนที่กดขณะมีแบบฟอร์มต้องรอ ไม่พาออกจากงานทันที
- Push เปิดรายเครื่องและเลือกภารกิจ/นัดหมาย/จดหมายได้ สูงสุด 3 เครื่องต่อคน ตรวจตาม scheduler ทุก 15 นาทีโดยใช้เวลาไทย ภารกิจช่วง 09:00 น., นัดภายใน 30 นาทีก่อนถึงเวลา, จดหมายหลังถึงวันเปิดอ่าน ไม่มีคำรับรองส่งถึงเครื่องตรงวินาที
- Push แสดงข้อความทั่วไป ไม่ส่งชื่อเรื่อง ชื่อคน ยอดเงิน หรือเนื้อหาจดหมายบนหน้าจอล็อก Deep link: Quest → `/quests`, นัด → `/explore/dates`, จดหมาย → `/explore/letters`, ทดสอบ → `/us` การกด Push ไม่ข้ามสิทธิ์บัญชี/การเปิดจดหมายตามเวลา
- Backup เป็นไฟล์เข้ารหัส `.olw-backup` สำหรับคู่เดิมบนเว็บเดิม ไม่สำรอง Passkey หรือบัญชี Restore แทนที่ข้อมูลทั้งคู่ มี preview และต้องพิมพ์ **กู้คืนข้อมูล**; การพิสูจน์ restore ต้องทำกับคู่ UAT เท่านั้น

ข้อเหล่านี้เป็นหลักฐานจาก source ไม่ใช่ผลรับรอง transport ของ Apple/Google, การแสดงผลบนโทรศัพท์ หรือผล UAT

### 3.2 อุปกรณ์และบัญชีที่ต้องมี

1. iPhone ที่มี Safari และตั้ง lock screen/ตัวจัดการ Passkey พร้อม; สำหรับ Push ต้องเป็น iOS 16.4 ขึ้นไปและเปิดแอปที่เพิ่มลง Home Screen แล้ว ตรวจตามรุ่นที่เจ้าของใช้งานจริง
2. Android ที่มี Chrome และตัวจัดการ Passkey พร้อม ตรวจ OS/browser version จริง ไม่ใช้ emulator แทน physical sign-off
3. บัญชี UAT A1/A2 เป็นคู่ A สำหรับการใช้งานพร้อมกันสองคน และ B1/B2 เป็นคู่ B สำหรับพิสูจน์แยกสิทธิ์ เก็บรหัสเชิญไว้ในช่องทางส่วนตัวเฉพาะรอบทดสอบ ไม่ใส่ใน screenshot หรือ commit
4. รูปสังเคราะห์ที่ไม่มีใบหน้าหรือ metadata ส่วนตัว ข้อความขึ้นต้น `UAT-` และยอดตัวอย่าง เช่น 10.01 บาท รายการเหล่านี้เป็นสมุดบันทึก ไม่มีการโอนเงินจริง
5. ก่อนการทดสอบเงิน/หัวใจ จดค่าคงเหลือและจำนวนประวัติ ก่อน/หลัง กำหนดผู้บันทึกเพียงคนเดียว อีกคนเป็นผู้ตรวจ อย่ากดรายการใหม่แก้ปัญหาเมื่อยังไม่ทราบผลรายการเก่า
6. อย่า uninstall PWA/ล้างข้อมูลเว็บไซต์ก่อนบันทึก pending receipt และผลรายการที่ยังไม่ทราบ หากไม่สามารถระบุได้ว่ารายการสำเร็จหรือไม่ ให้หยุดกรณีนั้นแล้วให้ผู้ดูแลตรวจ

### 3.3 ติดตั้ง iPhone ทีละขั้น

1. เปิด URL production ใน **Safari** โดยตรง หากเปิดมาจาก LINE ให้ใช้คำสั่งเปิดใน Safari
2. เปิดเมนู **แชร์**; Safari บางรูปแบบต้องกด **เพิ่มเติม** ก่อน แล้วเลือก **เพิ่มไปยังหน้าจอโฮม / Add to Home Screen**
3. เปิด **Open as Web App / เปิดเป็นเว็บแอป** ถ้ามีตัวเลือก แล้วกด **เพิ่ม**
4. แตะไอคอน **Our Little World** บน Home Screen ตรวจว่าเปิดแบบแอปและแถบล่างไม่ถูก Home indicator บัง
5. หากต้อง login ในหน้าต่างนี้ใหม่ ให้ใช้ Passkey เดิม ไม่สมัครชื่อผู้ใช้ใหม่เพื่อชดเชย cookie/session ที่ต่างโหมด
6. ไป `/us` รอข้อความเตรียมหน้าออฟไลน์พร้อม แล้วจึงเปิด Push ด้วยการกดปุ่มในแอป

ขั้นตอนติดตั้งอ้างอิง [คู่มือ iPhone ของ Apple](https://support.apple.com/en-lamr/guide/iphone/iphea86e5236/ios) ข้อกำหนด Push จาก Home Screen และการขอสิทธิ์จากการแตะของผู้ใช้ อ้างอิง [WebKit: Web Push for Web Apps on iOS and iPadOS](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/)

### 3.4 ติดตั้ง Android ทีละขั้น

1. เปิด URL production ใน **Chrome** โดยตรง ไม่ใช้หน้าต่างภายในแอปแชต
2. เปิดเมนู **⋮** เลือก **เพิ่มลงในหน้าจอหลัก / Add to home screen** แล้วเลือก **ติดตั้ง / Install** ตามเมนูที่ Chrome แสดง อาจมีคำสั่ง **ติดตั้งแอป** โดยตรง
3. เปิดไอคอนจาก Home Screen ยืนยันว่าเป็นเว็บแอปและ navigation ใช้งานได้
4. หากระบบขอ login ให้ใช้ Passkey เดิม รอเตรียมหน้าออฟไลน์พร้อมที่ `/us` แล้วทดสอบสิทธิ์ Push รายเครื่อง

เมนูอาจต่างตามรุ่น Chrome ใช้ [คู่มือ Google Chrome: Use web apps บน Android](https://support.google.com/chrome/answer/9658361?co=GENIE.Platform%3DAndroid&hl=en) เป็นแหล่งอ้างอิง หากติดตั้งได้เพียง shortcut ให้บันทึกพฤติกรรมจริง ห้ามสรุปว่า standalone ผ่าน

## 10. หลักฐานที่ต้องเก็บและข้อมูลที่ห้ามใส่

แต่ละข้อที่เปลี่ยนเป็น PASS/FAIL ให้แนบ `Test ID + รหัสเครื่อง + รุ่นแอป + เวลาไทย + เครือข่าย + ผลก่อน/หลัง + หมายเลขหลักฐาน` หากทดสอบกับสองคนให้บันทึกทั้งสองฝั่ง

- ภาพหรือวิดีโอควรเห็นปุ่ม/สถานะ/routeที่เกี่ยวข้อง ปกปิดชื่อบัญชีจริง รูปส่วนตัว ข้อความจดหมาย รหัสคำเชิญ endpointPush cookie Authorization challengeและcredentialเสมอ เก็บหลักฐานในที่ส่วนตัว ไม่commitลงrepo
- ผลเงิน/หัวใจต้องเห็นจำนวนประวัติและยอดก่อน/หลังที่ใช้นามแฝงสำหรับข้อมูลUAT; การเทียบแค่toastไม่พอ
- ผลPushต้องมีหน้าจอที่เห็นnotificationจริง แยกเวลาที่providerรับกับเวลาที่เครื่องแสดง; อย่าสรุปว่าเบื้องหลัง/ล็อกจอผ่านจากการทดสอบเฉพาะforeground
- ผลPasskeyต้องระบุว่าใช้authenticatorจริงชนิดใดและการloginด้วยอันสำรองสำเร็จหรือไม่ ห้ามถ่ายPIN/biometric promptที่เผยข้อมูลส่วนตัว
- ผลupdateต้องบันทึกรุ่นเก่า/ใหม่และเคยมีwaitingworkerจริง ห้ามเดาว่าเทียบรุ่นได้จากไอคอนเหมือนเดิม
- ถ้าระบบแสดงRequest IDให้เก็บเฉพาะค่าอ้างอิงสำหรับผู้ดูแล ไม่แนบrawlogsหรือrequestbodyส่วนตัวลงรายงานสาธารณะ

## 11. Stop Conditions และการจัดการปัญหา

หยุดการเขียนข้อมูลของรอบนั้นทันทีเมื่อพบข้อใดข้อหนึ่ง: เห็นข้อมูลอีกคู่; เงิน/หัวใจเพิ่มหรือหักซ้ำ; ติดลบโดยไม่ควร; privateรูป/จดหมายเปิดanonymous; อ่านจดหมายก่อนวัน; logoutแล้วrequestใหม่ยังผ่าน; restoreแทนข้อมูลโดยไม่ยืนยัน; updatereloadงานค้าง; หรือpendingรายการหายจนตรวจผลเดิมไม่ได้

1. ห้ามกดซ้ำเพื่อให้หาย ห้ามสร้างรายการชดเชย ห้ามลบหรือresetข้อมูลจริง
2. จดTest ID เวลาไทยและการกระทำสุดท้าย พร้อมหลักฐานที่ปกปิดข้อมูลแล้ว ถ้าคำตอบหายให้เก็บreceiptเดิมและตรวจผลเดิมหลังออนไลน์
3. แจ้งเจ้าของโปรเจกต์เป็นissueส่วนตัวด้วยขั้นตอนทำซ้ำ สิ่งที่คาดหวัง และสิ่งที่เห็นจริง แยกobservationจากการคาดสาเหตุ
4. เจ้าของอนุมัติfix/releaseก่อนdeployใด ๆ; retestเฉพาะบั๊กและflowใกล้เคียงที่อาจได้รับผล หลังอนุมัติแล้วบันทึกcommit/buildใหม่ให้ตรงรุ่น
5. ปัญหาPushจากFocus/permission/ไม่มีnetworkให้บันทึกenvironmentก่อน ไม่เปลี่ยนเป็นผ่านเพียงเพราะproviderตอบรับ และไม่เพิ่มpaidserviceเพื่อแก้รอบUAT
